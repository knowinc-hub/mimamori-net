# Phase 2 完了レポート — バックエンド・認証・データ実装

作成日: 2026-07-17 / 本番反映済み（PR #2, #3）

## 実装内容

### 認証・承認制（PR #2）
- Firebase Auth **メールリンク認証**（パスワードレス）。未ログイン・未承認では依頼情報を一切表示しない承認ゲート
- **招待コード必須の会員登録** → 承認待ち → 管理者承認（onSnapshot でリロード不要のライブ反映）
- 管理者は `admins/{uid}` コレクションで管理（Custom Claims 不使用。コンソールから追加）

### データ（PR #2）
- Firestore 構成: `requests`（メタ）/ `requests/{id}/private/main`（氏名・詳細・連絡先・写真＝**解決時に物理削除する対象を隔離**）/ `requests/{id}/updates`（寄せられた情報）/ `history`（日時・エリア・件数のみ）/ `users` / `inviteCodes` / `admins` / `reports`
- 写真は縮小 DataURL を private ドキュメントに保存。**Cloud Storage 不使用**（Spark プランで完結、削除が1ドキュメントで確実）
- 解決時はクライアントの batch write で本体・private・updates を物理削除し history を作成（history が「削除の事実」の記録＝監査ログを兼ねる）
- 下書きは端末ローカル（未投稿の個人情報をサーバに置かない）

### 管理画面・通報（PR #3）
- **管理タブ**（管理者のみ表示・非エンジニア向けUI）:
  - メンバー: 承認 / お断り / 停止 / 再開
  - 招待コード: 発行（読み間違えにくい文字でランダム生成）/ 無効化 / 有効化
  - 通報: 未対応一覧 → 投稿の非表示化 / 表示に戻す / 対応済みにする
- **通報機能**: 依頼カードの「問題を報告」→ 理由＋詳細。内容は管理者のみ閲覧可
- **投稿の非表示化**: `hidden` フラグ。セキュリティルールで一般メンバーの読み取り自体を遮断

### セキュリティルール（最優先事項・本番デプロイ済み）
- ユニットテスト **38件 全PASS**（`npm run test:rules`）
- 検証済みの遮断: 未ログイン/未承認の閲覧、他エリアの private 閲覧、自己承認、なりすまし投稿・通報、警察未届けの依頼作成、中身のない「反応」、履歴への個人情報混入、一般メンバーによる非表示解除
- エミュレータE2E: 認証〜解決 18項目＋管理フロー 13項目 全PASS

## 運用メモ

- メンバー承認・招待コード・通報対応は**すべてアプリの管理タブから**（コンソール不要）
- 管理者の追加だけはコンソールから: `admins` コレクションに対象者のUIDでドキュメント作成
- 旧データ注意: ルール更新前に作成された `hidden` フィールドの無い依頼は一覧に表示されない。残っていた場合はコンソールで `hidden: false`（boolean）を追加するか解決処理する
