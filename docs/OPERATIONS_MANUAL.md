# みまもりネット 運用マニュアル（草案）

管理者（承認・通報対応を行う人）向けの手引きです。**非エンジニアの方が読む前提**で書いています。
最終更新: 2026-07-17

## 0. 管理者ができること

アプリ下部の「**管理**」タブから、次の操作ができます（管理者にしか表示されません）。

| セクション | できること |
|---|---|
| メンバー | 登録申請の承認 / お断り、会員の停止 / 再開 |
| 招待コード | 団体向けコードの発行（ランダム生成）、無効化 / 有効化 |
| 通報 | 「問題を報告」された投稿の確認、投稿の非表示化、対応済み処理 |

このほか、依頼カード上で管理者は投稿者の代わりに「解決」処理ができます。

---

## 1. 日常の運用

### 1-1. メンバー承認の基準

新しい登録申請は「管理」→「メンバー」の「承認待ち」に表示されます。

- **承認してよい**: 表示されている所属団体（招待コードの配布先）の関係者であることが確認できる場合
- **確認してから**: 心当たりのないニックネーム・団体の組み合わせの場合は、その団体の窓口担当者に「この方はメンバーですか」と確認してから承認する
- **お断りする**: 団体側に確認しても誰か分からない場合

> 迷ったら承認しないでください。承認制であることが、このサービスの安全の土台です。

### 1-2. 招待コードの運用

- コードは**団体ごとに1つ**発行します（例: ○○学校PTA用、△△親の会用）。共用しないことで、流出時にそのコードだけを無効化できます。
- コードは「ランダム生成」ボタンで作るのが安全です。
- 配布方法: 団体の窓口担当者にのみ渡し、「団体内の必要な方だけに共有し、SNS等には書かないでください」と依頼します。
- **無効化する場合**: コードが外部に漏れた疑いがあるとき、団体との提携を終了したとき。無効化しても登録済みメンバーには影響しません（新規登録に使えなくなるだけ）。

### 1-3. 捜索依頼が投稿されたとき

1. 依頼の内容を確認します。明らかにいたずら・虚偽と思われる場合は「2-2. 虚偽投稿への対応」へ
2. 通常は特に操作は不要です。エリア内のメンバーが「見かけた」「情報提供」で協力します
3. 依頼から時間が経っても解決処理がされない場合は、投稿者に連絡し、状況を確認して解決処理を促します（発見済みなのに情報が残り続けるのを防ぐため）
4. 投稿者と連絡が取れない場合、管理者が「解決」処理をしてください（情報は自動削除されます）

## 2. トラブル対応

### 2-1. 通報が届いたとき

「管理」→「通報」の「未対応」に表示されます。

1. 通報の理由と対象の投稿を確認する
2. 問題があると判断したら「**投稿を非表示にする**」（メンバーから見えなくなります。判断に迷う間の一時措置としても使えます）
3. 投稿者側に問題がある場合は「メンバー」から該当会員を**停止**する
4. 対応が終わったら「**対応済みにする**」を押して記録を残す

問題がなかった場合（通報が誤解だった場合）は、そのまま「対応済みにする」だけでOKです。

### 2-2. 虚偽投稿への対応

1. まず投稿を「**非表示**」にする（拡散を止めるのが最優先）
2. 投稿者の会員を「**停止**」する
3. 実在の人物の情報が虚偽の文脈で使われていた場合など、悪質な場合は警察への相談を検討する
4. 影響を受けた団体の窓口に経緯を連絡する

### 2-3. 情報の外部転載を見つけたとき

1. 転載先（SNS等）のスクリーンショットを保存する（証拠）
2. 転載した人物が会員として特定できる場合は利用停止
3. 転載先のプラットフォームに削除依頼を出す
4. 依頼の当事者（家族）に事実を連絡し、謝罪と経緯説明を行う
5. 再発防止のため、必要に応じて該当団体の招待コードを無効化して再発行する

### 2-4. 本人・家族から削除の要望があったとき

- 依頼がまだ「捜索中」の場合: 投稿者に確認のうえ「解決」処理（情報は自動削除されます）
- すでに解決済みの場合: 詳細情報は削除済みです。履歴（日時・エリアのみ）の削除も希望される場合は、開発担当に依頼してください

## 3. 年次の引き継ぎ（管理者交代）

年度替わり等で管理者を交代する場合の手順です。

### 3-1. 新しい管理者の追加（現管理者＋開発担当で実施）

1. 新管理者に、通常の手順（招待コード→登録→承認）でメンバーになってもらう
2. Firebase コンソール（console.firebase.google.com）の Firestore → `users` で新管理者のドキュメントを開き、**ドキュメントIDをコピー**する
   - ⚠️ IDは必ず画面からコピー&ペーストする。手入力は厳禁（似た文字の間違いで動かなくなります）
3. `admins` コレクションに、そのIDをドキュメントIDとして新規ドキュメントを作成（フィールド: `createdAt` = 0）
4. 新管理者のアプリに「管理」タブが表示されることを確認する

### 3-2. 旧管理者の除去

1. `admins` コレクションから旧管理者のドキュメントを削除する
2. 会員として残る場合はそのまま、退会する場合は「メンバー」から停止する

### 3-3. 引き継ぐアカウント・権限の一覧

| 対象 | 場所 | 引き継ぎ方法 |
|---|---|---|
| アプリの管理者権限 | Firestore `admins` | 上記 3-1 / 3-2 |
| Firebase プロジェクト | console.firebase.google.com | プロジェクト設定→「ユーザーと権限」でオーナー権限を付与・移譲 |
| GitHub リポジトリ | github.com/knowinc-hub/mimamori-net | Settings → Collaborators |
| 招待コードの配布記録 | 各団体の窓口担当者リスト | 【団体窓口リストの管理場所を決める】 |

### 3-4. 引き継ぎ時に必ず伝えること

- このサービスの設計原則（SNS共有しない・解決したら消える・承認制・警察届出前提）— 詳細は `docs/PRODUCTION_PLAN.md` 第2章
- 本マニュアルと利用規約・プライバシーポリシーの場所
- 開発担当（現在: 【担当者名・連絡先】）への連絡方法

## 4. 困ったとき

| 症状 | 対処 |
|---|---|
| 管理タブが表示されない | 一度アプリをリロード。それでも出ない場合は `admins` のドキュメントIDがUIDと一致しているか確認（3-1参照） |
| メンバーがログインできない | 迷惑メールフォルダの確認を案内。メールリンクは送信元が Firebase のドメインです |
| 「データを読み込めませんでした」 | 「再読み込み」ボタン。続く場合は開発担当へ |
| 上記以外の不具合 | 開発担当へ連絡: 【連絡先】 |
